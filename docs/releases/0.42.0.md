# 0.42.0

## Warden Nodes — policy and list synchronization (BETA)

Warden can now run as a cooperating set of nodes instead of a single
resolver. One node acts as the primary; the others join it, authenticate,
and receive its policy and blocklist state, so a change made once is
reflected everywhere without hand-copying configuration between machines.

Onboarding is guided: the primary issues a short-lived association token,
the joining node presents it, and the pair establishes an authenticated,
certificate-pinned channel. Nodes are durable — they survive restarts and
reappear with their last known state rather than vanishing from the
cluster.

This is a **beta**. It is off unless you configure it, a single-node
install is completely unaffected, and the synchronization protocol may
still change incompatibly between releases. Try it on machines you can
afford to re-provision, and report what breaks.

## Reworked terminal UI

The Dashboard and Query Log have been rebuilt around the layouts operators
actually kept open.

- The Dashboard presents block rate, traffic, query types, upstream and
  memory state as consistent cards with explicit labels, responsive
  scrolling, and hour/date inspection — and keeps real warnings in the
  header instead of hiding them behind decoration.
- The Query Log has one filter row (Domain, Client, Period, Blocked, and
  an Advanced view), a single-key picker, a 3-hour preset, and shared
  modal styling throughout. Long error messages no longer destroy your
  in-progress form input; drafts survive.
- Device labels are now persistent, named categories you can reorder from
  the Configuration view, and device dialogs follow the same layout rules
  as the rest of the interface.
- Polling and disk writes moved off the input event loop, so the
  interface stays responsive while it refreshes.

## Safer operator rules and configuration changes

The policy engine behind operator-defined rules has been reworked end to
end, with an emphasis on never leaving the daemon in a half-written state.

- Policy writes are transactional: a change either applies completely or
  not at all, and a failed write cannot strand a partial rule set.
- The configuration schema has moved forward (v4 → v5). The migration is
  deterministic, runs once, and keeps a backup; a daemon that cannot
  migrate refuses to start on the unknown schema rather than guessing.
- Reloads are generation-safe: a new configuration is validated as a
  complete generation before it replaces the active one, so a broken
  reload keeps the last good policy serving.
- Cluster policy artifacts are coherent across nodes: every member of a
  synchronized set evaluates the same policy generation.

Existing configurations migrate automatically on first start; no manual
steps are required.

## Fixes

- Draft text in TUI forms is preserved across long profile errors,
  refreshes, and view changes.
- DoH upstreams that require HTTP/2 now work; previously such providers
  answered every query with a failure while the daemon reported healthy.
- The security update to the HTTP/2 dependency (`h2` 0.4.16) is included.
